# BMS数据接入与质量检查 V0.2

输入两张CSV：`telemetry_template.csv`的核心时序字段，以及新增`metadata_v02_template.csv`的静态信息。原38项需求清单及六张采集模板仍保留。本版程序只核查核心时序和元数据；全部单体、探针、事件及容量检测长表尚未接入自动校验。

## 运行自己的数据

```console
python -m src.bms_validate --telemetry 我的时序.csv --metadata 我的元数据.csv --output results/my_bms
```

元数据需明确电压V、电流A、温度degC、SOC百分数%、化学体系、额定容量Ah、电流符号及`data_origin`来源说明。输入单位不匹配时报错，不猜测mV到V等转换。`current_sign_convention`可取`discharge_positive`或`charge_positive`；程序按明确声明统一成放电正，保留`pack_current_raw`和原始行号。电池ID按文本读取，保护前导零。

时间戳必须包含Z或明确UTC偏移，例如`2026-01-01T08:00:00+08:00`。输出统一UTC。无时区记录、缺失或非数值核心字段、SOC越界、极值倒置、无对应元数据的电池ID均隔离。同电池同时间戳出现重复，全部重复行隔离，避免任意挑一条。

结果包括`accepted.csv`、`rejected.csv`、`issues.csv`、`normalized_metadata.csv`和`summary.json`。再次导入已标准化的accepted时必须配套使用normalized_metadata，避免重复反转电流。`source_csv_row`指本次输入CSV的行号，表头为第1行。summary包含源文件SHA256，但来源声明不等于程序已核实授权或真实性。

警告包括时间断档、原始顺序混乱、电流方向与状态不一致、缺少里程等；警告不会自动删除记录，需要审阅。`--max-gap-s 30`设置断档阈值，跨断档不得直接积分，程序本身不计算Ah或SOH。电压/温度范围为宽松的输入合理性规则，不是电池安全阈值；可见`src/bms_validate.py`中的BOUNDS。

退出码0表示非空且无错误的核心数据检查，退出码2表示空表、缺字段或数据错误。有警告时仍可返回0，必须检查warnings_need_review。通过检查不意味着安全合格、车型模型适用或SOH/RUL可预测。本版明确不把整包数据输入NASA实验电芯模型。

## 演示证据

`synthetic_fixtures`全部是软件测试构造数据，电池ID和data_origin均明确标识；不是车企/车主数据，也不是NASA数据转换成的整包记录。

```console
python -m src.bms_fixtures
python -m src.bms_validate --telemetry bms/synthetic_fixtures/good_telemetry.csv --metadata bms/synthetic_fixtures/metadata.csv --output results/bms_good
python -m src.bms_validate --telemetry bms/synthetic_fixtures/bad_telemetry.csv --metadata bms/synthetic_fixtures/metadata.csv --output results/bms_bad
```

预期：好文件12行通过；坏文件13行中6行隔离，7行保留并带可审阅警告，退出码2。请勿把测试通过描述为“已接入真实车辆”。
