# 生命周期碳足迹计算器 V0.1

公式：每行排放（kgCO2e）= 活动量 × 对应排放因子；分阶段求和。可编辑 `carbon_factors.csv` 和 `example_activities.csv`，保存后重新运行。使用 UTF-8 CSV，不要将空白填成0。

```console
python -m src.carbon --allow-demo
python -m src.carbon --activities carbon/my_activities.csv --factors carbon/carbon_factors.csv --output results/my_carbon
```

第一条命令明确允许演示因子和演示活动量；第二条用于自行填报，默认拒绝演示数据。`status=pending` 或缺失因子始终报错。`official/verified` 是输入方对来源的声明，程序不会替代人工审查报告。可增加任意活动行；活动ID和因子ID分别须唯一。阶段只能为 manufacturing、use、maintenance_transport、end_of_life。

## 示例边界与功能单位

功能单位为“1套假设60 kWh、400 kg电池包，在假设首个使用寿命内的制造、循环损耗、维护运输、退役处理”。所有活动量及制造/货运/退役因子均为明确的演示参数，不是本项目实测值。使用阶段只归集电池能量损耗：假设生命周期输入30000 kWh，输出27000 kWh，差额3000 kWh。示例不含充电设备损耗；若表计边界不同，应分离充电设施损耗。不能将此结果称为整车生命周期碳足迹。

若分析整车用电场景，可把使用活动量改为电网侧总输入电量，但必须相应修改功能单位和归属规则。两种边界不能相加。电网侧计量电量已经包含的损耗不得再次增加。

制造因子假设为材料获取到电池包出厂的综合值，不另加其已含的制造用电。维护仅包含假设检测用电，不代表真实项目无更换材料；如存在更换，应单独添加活动及经过核实的材料因子。货运量须用吨×公里，不能把千克当吨。退役处理按处理质量×因子计算，不自动抵扣再生材料收益。多路径分流时，各路径质量总和须与总退役质量一致并人工校核。

本版采用退役截断分配，无避免排放、替代收益或第二寿命分摊。尚未实现材料清单LCA、数据库连接、时间动态电网、敏感性区间、正式产品类别规则和第三方核查。输出中的 `scope_complete` 仅表示四阶段均有输入，不表示LCA边界完整或已合规。

## 因子依据

全国电力平均碳足迹因子 **0.5777 kgCO2e/kWh（2024年度）**，已核对[生态环境部官方解读](https://www.mee.gov.cn/ywdt/zbft/202510/t20251024_1130763.shtml)及[发布公告](https://www.mee.gov.cn/xxgk2018/xxgk/xxgk01/202510/t20251024_1130734.html)。这是明确年份的生命周期因子，并非声称为所有场景适用的最新因子。正式使用需按发生年份、地域、市场化电力采购和适用核算规则审核；不能与仅CO2排放因子混用。

其余演示因子在CSV中无外部来源，严禁在报告中包装成官方或行业均值。正式因子建议来自供应商核查报告、明确版本的LCA数据库或原始研究，记录体系、地区、年份、工艺、GWP版本、系统边界、分配和不确定性。

输出 `carbon_detail.csv` 可追溯活动、因子和逐项排放；`carbon_summary.json` 包含分阶段合计、缺失阶段和演示标记。脚本拒绝缺失或重复因子、非数值/无穷/负数活动量和因子、单位不匹配。不支持负因子回收信用，防止本版中未经定义的抵扣。
