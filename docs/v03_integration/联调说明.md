# 给Web Demo组员的联调说明

本包提供算法侧接口和示例JSON，不含新的Web界面。接口已在本地真实HTTP请求中测试；尚未取得组员的Web代码或地址，因此不能称已完成双方实际页面联调。

## 启动

Python 3.12，在包根目录执行：

```console
python -m pip install -r requirements.txt
python -m src.api_server --port 8013 --allowed-origin http://localhost:3000
```

服务监听127.0.0.1，不会发布到公网。把allowed-origin改成实际本地前端源，或由现有Web后端转发请求。前端调用范例在frontend_client.js。停止服务按Ctrl+C。

## 端点

| 端点 | 方法 | 输入 | 结果 |
|---|---|---|---|
| /health | GET | 无 | 服务模式和schema_version |
| /v0.3/explain | POST | battery_id、整数cycle | 保存的NASA样本SOH预测、SHAP贡献、基准值及观测值 |
| /v0.3/decision | POST | scenario，可选weights | 模拟约束结果、四路径目标、Pareto集合、偏好推荐 |
| /v0.3/report | POST | model_case、scenario，可选weights | 实验电芯证据与模拟电池包决策的分区组合报告 |

POST使用application/json，最大1MiB。返回400表示参数不合法，415表示内容类型不对，404表示端点不存在，500表示运行依赖/文件/配置异常。安全证据不足属于正常业务结果，HTTP仍为200，但recommended_route=null，必须显示“待补证据/专业复核”，不能显示推荐成功。

示例请求example_report_request.json可直接发送。也可不启动服务：

```console
python -m src.integration --action report --request integration/example_report_request.json --output example_response.json
```

## 前端展示约定

1. model_evidence是NASA公开实验电芯，scenario_decision是另外的模拟电池包情景；automatic_model_to_pack_transfer固定false。两者不能显示为同一辆真实车的诊断。当前接口不接受任意车辆BMS直接推断SOH。
2. SHAP展示“对预测的贡献（百分点）”，正/负相对于base_value_soh_pct，不写“衰减原因贡献比例”。measured_soh_pct只是离线实验标签，未来实车没有此标签时不得伪造。
3. RUL来自V0.2探索性模型，需要截至当前循环结束的实测容量；SOH是在放电600秒时预测。两者信息可用时点不同，不能把RUL当成600秒时已经能得到的无容量测试结果。
4. 先展示eligible和reason_codes，再显示得分。null得分表示未进入排序，不能当0参与推荐；pareto_optimal不等于安全通过之外的认证。
5. carbon_kgco2e、npv_cny、recovered_kg、technical_score均来自示例参数。前瞻处置碳结果与V0.1历史全生命周期总量不能直接相加。
6. health.rul_unit必须为reference_discharge_cycles；真实天数或公里不能直接代入。data_kind取vehicle_unvalidated会停止自动建议。

输入结构见request.schema.json。重要输出键不会省略：schema_version、status、recommended_route（可null）、routes、reason_codes等。权重可改，安全门槛不能从请求体覆盖；成本/材料/参数在服务侧decision目录编辑后生效。

联调验收：正常例显示模拟推荐；缺证据例显示待复核；critical_event=true所有路径停止；post_repair_pass=null不得推荐检修后使用；RUL=1排除继续利用路径；非法字符串false返回400；模型电芯ID不存在返回400。不要把这些构造测试称为实车验证。
